# HomeDB 自适应分组侧边栏设计

## 背景

HomeDB 当前把分组导航放在内容顶部。用户主要在电脑浏览器中按分组浏览，VPS 等首屏分组使用频繁，页面下方的低频分组因为标题不够醒目而容易被忽略。分组和书签已有固定顺序，尤其 VPS 书签按序号排列，因此不能用自动重排解决发现性问题。

## 目标

- 在桌面端持续展示全部分组，强化低频分组的可见性。
- 保持现有分组和书签顺序，不引入自动排序或推荐。
- 桌面侧边栏可手动收起，并在本机记住状态。
- 移动端使用支持滑动手势的左侧抽屉，不长期占用屏幕宽度。
- 侧栏显示分组颜色、名称和书签数量，并随正文滚动高亮当前分组。
- 保留现有搜索、常用书签、管理模式、同步、导入导出和主题行为。

## 非目标

- 不修改导航数据结构、Blob 数据格式或同步策略。
- 不增加访问历史、自动推荐、最近使用或自动排序。
- 不在侧边栏重复展示组内书签。
- 不提供第二套分组拖拽入口。
- 不同步侧边栏展开状态到云端。

## 桌面体验

在 `lg` 及以上视口使用左右布局。侧边栏固定在左侧，展开宽度约 220px；正文占据剩余空间，并继续使用现有最大内容宽度和书签网格。

侧栏顶部固定显示“分组”，站点标题仍只保留在现有顶部栏，避免重复。每个分组项包含原有颜色标记、完整分组名称和书签数量。当前分组使用强调背景、左侧边线和更高文本对比度。点击分组后平滑滚动到对应正文区块，并考虑固定顶部工具栏的偏移。

侧栏底部提供图标收起按钮。收起后宽度约 56px，只保留颜色标记；悬停或键盘聚焦时通过 tooltip 显示分组名称。展开状态写入本机 `localStorage`，刷新和再次打开时恢复。正文宽度随侧栏动画稳定变化，不重排导航数据。

桌面端移除 QuickBar 中现有的横向分组链接，避免两套导航重复。搜索和常用书签继续位于正文顶部。

## 移动体验

低于 `lg` 的视口不显示固定侧栏。顶部栏左侧提供菜单按钮，打开覆盖式左抽屉。抽屉宽度约为视口的 78%，最大 320px，内部复用桌面侧栏的分组内容。

抽屉支持以下关闭方式：向左滑动、点击遮罩、按 Escape、点击目标分组。点击分组后先关闭抽屉，再平滑滚动到目标。打开时锁定背景滚动并保持焦点约束。

使用项目现有的 Vaul 抽屉能力处理动画、遮罩、焦点和拖动关闭。在页面左缘提供有限的右滑打开手势区域，避免干扰正文的上下滚动。手机顶部不再显示横向分组导航，搜索框仍直接可用。

## 搜索与管理状态

正常浏览时显示每组书签总数。搜索时仍保留全部分组：有结果的分组显示匹配数量并可跳转；没有结果的分组降低透明度且不可跳转。清空搜索后恢复总数和全部导航能力。

新增、删除、改名或重排分组后，侧栏按当前 `order` 立即更新。管理模式下仍只在正文区域拖拽分组；侧栏作为导航和状态视图，不参与编辑。

## 当前分组判定

新增 `useActiveGroup` hook，使用 `IntersectionObserver` 观察正文分组元素。判定区域考虑固定顶部栏和 QuickBar 高度，优先选择最接近内容视口顶部且仍可见的分组。

用户点击侧栏项目时立即设置目标高亮，随后由观察器接管。滚动经过页面底部时，最后一个可见分组保持高亮。搜索过滤或分组删除后，如果当前 id 不再存在，则回退到第一个可见分组。

## 组件边界

- `GroupSidebarContent`：渲染共享分组列表、数量、颜色、高亮和可用状态。
- `DesktopGroupSidebar`：负责固定布局、展开/收起、tooltip 和本机偏好。
- `MobileGroupDrawer`：负责移动抽屉、菜单触发器和关闭行为。
- `useActiveGroup`：负责正文观察和当前分组状态。
- `QuickBar`：移除横向分组链接，只保留搜索和常用书签。
- `NavApp`：组合响应式布局、准备搜索计数并连接导航动作。

共享侧栏内容只接收已排序分组、显示数量、当前 id、折叠状态和点击回调，不直接访问 store 或 DOM。这样桌面与移动端共用展示逻辑，而容器各自处理布局和交互。

## 本地状态

使用独立键 `mininav_sidebar_collapsed` 保存桌面收起偏好。值只接受 `1` 或不存在。读取失败时默认展开，写入失败不影响导航。移动抽屉开关只存在于当前 React 会话，不持久化。

## 可访问性与动效

- 分组项使用原生按钮，支持 Tab、Enter 和 Space。
- 当前分组通过 `aria-current="location"` 标记。
- 收起按钮和移动菜单按钮提供明确的 `aria-label`、状态和 tooltip。
- 抽屉打开后焦点进入抽屉，关闭后返回触发按钮。
- 动画时长控制在 180 至 220ms，并遵守 `prefers-reduced-motion`。
- 分组名称截断时保留 tooltip，数量使用可读文本而非仅靠颜色表达。

## 异常与边界处理

- 点击后目标元素已不存在时保持当前位置，不显示错误提示。
- 搜索无结果时所有分组项变为不可用，正文继续显示现有无结果状态。
- 没有任何分组时侧栏显示空状态，管理模式下正文仍可创建第一组。
- 极长分组名称在展开态单行截断，在 tooltip 中显示完整名称。
- 侧栏内容超过视口高度时内部滚动，不推动整个页面。

## 验证计划

- 为侧栏偏好读写、搜索数量和活动分组回退逻辑编写单元测试。
- 运行完整 Vitest、严格 ESLint、TypeScript 和 Next.js 生产构建。
- 在约 1440x900 的桌面视口验证展开、收起、状态记忆、点击定位和滚动高亮。
- 在约 390x844 的移动视口验证按钮打开、边缘右滑、左滑关闭、遮罩关闭和点击定位。
- 验证搜索、管理模式分组变更、空数据、长名称和三种主题。
- 检查侧栏、顶部栏、QuickBar、正文和抽屉之间没有遮挡、抖动或文字溢出。

## 验收标准

1. 桌面首屏始终能看到全部分组名称、颜色和数量，除非用户主动收起侧栏。
2. 侧栏不改变任何分组或书签顺序。
3. 点击分组能稳定定位，滚动正文能准确更新高亮。
4. 桌面收起状态在刷新后保持，且不影响其他设备。
5. 移动抽屉可通过按钮和边缘手势打开，并可通过手势、遮罩、Escape 或选择分组关闭。
6. 搜索时数量和可用状态正确，清除搜索后完全恢复。
7. 现有导航、编辑、拖拽、同步、认证、导入导出和主题功能无回归。
